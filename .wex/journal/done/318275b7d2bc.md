# Une extension de champ `open` : ouvrir ce que la valeur désigne

Opened: 2026-11-14
Updated: 2026-11-14
Status: fait côté design system (2026-11-14)
Author: agent:main (Syrtis), pour l'agent du design system — demandé par weeger

## Pourquoi

Un champ dont la valeur désigne quelque chose qu'on peut consulter — un pipeline, un scénario, un
content type, un storage, une session — ne permet pas d'aller le voir. Il faut quitter le
formulaire et le chercher ailleurs. weeger veut, une fois une valeur choisie, pouvoir cliquer pour
l'ouvrir : dans un nouvel onglet, une modale ou un panneau, selon le cas.

Choisi avec lui (2026-11-14) : **une extension de champ**, pas un nouveau type de champ ni un
« select d'entité » qui s'affiche en barre cliquable. Raisons :

- elle vaut pour **tout champ** : un select, un `search-select-input`, un champ texte — et pas
  seulement pour des entités ;
- une application l'ajoute par une option du champ, comme elle le fait déjà pour `versions` ;
- pas de nouvelle forme de champ à maintenir ; un champ qui se change en barre une fois rempli rend
  la valeur plus difficile à modifier.

## Ce qui existe

`assets/js/Helper/FieldExtensionsHelper.ts` : le registre des extensions (`expression`,
`versions`), dessinées par la base des champs (`_abstract/form-field`) en `header` ou en `footer`
du contrôle, avec leurs options (`extensions: { versions: { url } }` dans la définition du champ,
côté PHP par l'option `extensions` du type de champ). `versions` met l'id de l'enregistrement là où
son adresse a `__id__` (`FORM_DEFINITION_ID_PLACEHOLDER`). Le DS a `modal`, `panel` et `overlay`.

## Ce qui est demandé

Une extension `open` :

- **une icône** (par ex. `ph:bold/arrow-square-out`), à côté de la valeur, dans le cadre du champ
  plutôt qu'en header ou en footer. Il faudra sans doute une nouvelle place pour les extensions,
  dans le cadre (comme les addons `prefix` / `suffix` de `text-input`) ;
- **active seulement quand le champ a une valeur** ; désactivée ou cachée sinon ;
- **options** :
  - `url` : l'adresse modèle, la valeur mise à la place de `__value__` (et `__id__` comme pour
    `versions`, si utile) ;
  - `target` : `tab` (nouvel onglet), `modal`, ou `panel` — ce qui est ouvert est la page à cette
    adresse, ou, pour `modal` / `panel`, ce que le DS sait y charger ;
  - `label` : ce que dit l'icône au survol (par défaut « Open »).
- **même chose en twig et en vue**, comme `versions` (le thème de formulaire twig et `dynamic-form`).

## Où Syrtis s'en servira

- Slot `pipeline` / `pipeline_read` / `pipeline_purge` : le pipeline choisi (champ `pipeline`,
  un `search-select-input`) ouvre son éditeur.
- Op `scenario` d'un pipeline : le scénario choisi ouvre son éditeur.
- `content-type-input` (Syrtis, `search-select-input` préréglé) : le type choisi ouvre sa fiche.
- Hors formulaire, l'éditeur de pipeline a un select des « états » d'un pipeline (scopes) : le même
  bouton à côté ouvrirait la session ou l'utilisateur. Ce n'est pas un champ de formulaire ; si
  l'extension se pose aussi sur un select nu, tant mieux, sinon Syrtis posera le bouton à la main.

## Hors scope

- Afficher la valeur choisie sous forme de carte ou de barre.
- Les champs qui dépendent les uns des autres : ticket `c77cd12157ba`.

## Fait (2026-11-14, agent DS)

- Norme `json-schema` 3.5.0 (`8d9a5b5`) : `extension_open.schema.json`, `open` dans `field_base`.
- `symfony-forms` (`1da0dd6`) : `OpenFieldExtension` — `url` (requis), `in` (`tab` par défaut, `modal`, `panel`), `label` ; `__id__` remplacé côté serveur pour un champ dessiné.
- Design system (`00b9a41`) : `form/extension/open`, nouvelle place `end` (bouton collé au bout du cadre du champ, grisé sans valeur), vue et twig ; doc `usage/form-fields`.
- **Attention : l'option s'appelle `in`, pas `target`** — `target` est déjà ce que le DS donne à toute extension d'un champ twig (l'id de son contrôle).

```php
'extensions' => ['open' => ['url' => '/projects/'.$projectId.'/pipelines/__value__/editor', 'in' => 'tab']]
```

- Vérifié dans le navigateur côté vue (dynamic-form) : bouton collé, grisé vide, réactivé à la saisie, ouverture en modale avec la valeur encodée. Côté twig : écrit, pas vu à l'écran.
