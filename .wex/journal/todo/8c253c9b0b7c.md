# Champ clé / valeur dans les formulaires (Symfony + dynamic-form)

Opened: 2026-11-05
Updated: 2026-11-05
Author: agent:main (Syrtis)

## Besoin

Syrtis (`SYRTIS/local/api`) édite les règles de sortie d'un slot (`SlotOutput`) depuis le slot editor du board, par `SlotOutputForm` servi à `dynamic-form` (`form_definition_for(…, { id_placeholder })`). Une règle porte des **métadonnées** : un objet JSON clé → valeur (`?array $metadata`), appliqué aux messages enregistrés. Aujourd'hui ce champ n'est pas éditable : aucun type de formulaire ne le porte jusqu'à `dynamic-form`.

## Constat

- Le DS a déjà le composant Vue : `assets/components/form/key-value-input` (`modelValue: [{ key, value }]`).
- symfony-forms n'a pas de type Symfony qui lui corresponde (`src/Form/Type/` : pas de KeyValue).
- `FormDefinitionBuilder::buildField()` n'envoie qu'une valeur scalaire (`'value' => is_scalar($value) ? … : null`) : une liste ou un objet part vide.
- `dynamic-form.vue.twig` ne dessine que `text`, `textarea`, `select` (+ le texte par défaut) : `TagsInputType` arrive lui aussi en simple texte (`type: text`, valeur « a, b ») — même manque, à traiter dans la foulée si c'est le même chantier.

## À faire

- [x] Un type `KeyValueInputType` (symfony-forms) : modèle `array<string, scalar>` (objet), vue en liste de paires ; transformer dans les deux sens ; posté paire par paire sous son index (`form[field][0][key]`). **Écart** : une ligne vide est écartée, mais une clé en double ou une valeur sans clé est **refusée** (erreur de champ, `invalid_message`), pas écartée — on ne perd pas en silence ce que la personne a tapé. Rien d'écrit donne `null`. Les valeurs sont du texte (`2` revient `"2"`, `true` revient `"true"`).
- [x] Son schéma dans la norme (`web/key_value_input.json`, json-schema 1.2.0). **Écart** : les paires sont dans `pairs`, pas dans `value` — `field_base` impose `value: string|null` à tous les champs, une liste ne peut pas y tenir. `FormDefinitionBuilder` envoie `pairs`.
- [x] `dynamic-form` : le type `key_value` dessiné par `key-value-input`, envoyé paire par paire ; `values` accepte la liste de paires ou l'objet.
- [x] Les deux rendus jumeaux : `key-value-input.html.twig` + `.ts` (bloc `key_value_input_widget` du thème) et la vue, même feuille. Composant refait au passage : une seule bordure, deux colonnes alignées, clés en mono, la dernière ligne est la paire suivante écrite en place, × au survol, clé en double signalée.
- [ ] `tags` dans `dynamic-form` : **pas fait, chantier à part.** Même manque (valeur liste), mais autre type et autre composant ; à ouvrir quand un besoin réel arrive.
