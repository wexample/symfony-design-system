# Champ clé / valeur dans les formulaires (Symfony + dynamic-form)

Opened: 2026-11-05
Updated: 2026-11-05
Author: agent:main (Syrtis)

## Besoin

Syrtis (`SYRTIS/local/api`) édite les règles de sortie d'un slot (`SlotOutput`) depuis le slot editor du board, par `SlotOutputForm` servi à `dynamic-form` (`form_definition_for(…, { id_placeholder })`). Une règle porte des **métadonnées** : un objet JSON clé → valeur (`?array $metadata`), appliqué aux messages enregistrés. Aujourd'hui ce champ n'est pas éditable : aucun type de formulaire ne le porte jusqu'à `dynamic-form`.

## Constat

- Le DS a déjà le composant Vue : `assets/components/form/key-value-input` (`modelValue: [{ key, value }]`).
- symfony-forms n'a pas de type Symfony qui lui corresponde (`src/Form/Type/` : pas de KeyValue).
- `FormDefinitionBuilder::buildField()` n'envoie qu'une valeur scalaire (`'value' => is_scalar($value) ? … : null`) : une liste ou un objet part vide.
- `dynamic-form.vue.twig` ne dessine que `text`, `textarea`, `select` (+ le texte par défaut) : `TagsInputType` arrive lui aussi en simple texte (`type: text`, valeur « a, b ») — même manque, à traiter dans la foulée si c'est le même chantier.

## À faire

- [ ] Un type `KeyValueInputType` (symfony-forms) : modèle `array<string, scalar>` (objet), vue en liste de paires ; transformer dans les deux sens ; paires vides et clés en double écartées ; posté sous un nom de champ que `dynamic-form` sait envoyer.
- [ ] Son schéma dans la norme des champs (`key_value`), pour que `FormDefinitionBuilder` le reconnaisse (`buildKind`) et en envoie la valeur structurée (liste de paires) plutôt que rien.
- [ ] `dynamic-form` : le type `key_value` dessiné par `key-value-input`, envoyé comme le type le lit.
- [ ] Les deux rendus (twig `*.html.twig` et Vue) jumeaux, comme les autres champs.
- [ ] (Même chantier, à confirmer) `tags` : `dynamic-form` dessiné par `tags-input`, valeur en liste.
