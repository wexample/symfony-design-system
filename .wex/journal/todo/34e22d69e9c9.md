# Paquets git : php-git, symfony-git, symfony-git-ds (historique paginé par l'API)

Opened: 2026-10-16
Updated: 2026-10-16
Author: agent:addon:ai/editor (app-board)

## Contexte
Le board (app-board) a un outil « Git » dans le dock de chaque app : une toolbar avec l'interrupteur auto-commit à droite, et en dessous l'historique git de l'app. Pour l'instant, l'historique est rendu côté serveur : les 100 derniers commits, avec `graph_log` du DS. Certains projets ont des années d'historique, donc à terme il faut un historique **paginé et rechargeable**, ce qui veut dire passer par l'API et le modèle d'entité de la suite (DTO, schéma exporté, entité TypeScript, repository js-api).

## Où est le code git aujourd'hui (éparpillé)
- `symfony-helpers` / `Service/GitRepositoryReader.php` : `status`, `commit`, `log($repository, $limit, ?$path)`, `isBusy`.
- `symfony-wex` / `Service/WorkdirCommitter.php` : commite des chemins donnés, en tant que propriétaire du repo (`setpriv`).
- `symfony-design-system` / `Twig/GraphLogExtension.php` : `graph_log(commits)`, le dessin du graphe.
- `symfony-coding` / `Twig/GitGraphExtension.php` : **un autre** graphe git. Doublon à examiner.
- app-board : `AppCloner` (`git clone`), `AppWorkdirLinker`, `AppFileHistory`, `AppRepositoryState`.

## Proposition (validée dans le principe par l'opérateur)
- **php-git** : la lecture (`log` paginé avec curseur ou offset, `status`, `show`) et l'écriture (commit de chemins donnés, en tant que propriétaire du repo). PHP pur sur `symfony/process`. Y déplacer `GitRepositoryReader` et `WorkdirCommitter`.
- **symfony-git** : le bundle. Un endpoint d'API paginé « commits d'un repository » (optionnellement filtré par chemin), le DTO d'un commit (hash, parents, refs, auteur, date, sujet), les services.
- **symfony-git-ds** : le composant Vue du graphe, paginé (chargement à la demande, rechargement), branché sur le repository js-api. Il remplace `graph_log` (twig, DS) et le graphe de symfony-coding.

## Point à trancher en premier
Un commit n'est pas une ligne Doctrine. La chaîne `#[ApiEntity]` de symfony-api (DTO → `api:export:entities` → `generate-entities` / `generate-repositories`) est faite pour des entités Doctrine. Il faut vérifier si symfony-api sait servir une ressource **non persistée** (lue ailleurs, ici par git), et sinon l'y ajouter. C'est le vrai travail : le reste est du déplacement.

## Consommateurs à migrer ensuite
- app-board : l'outil Git (historique de l'app) et l'historique d'un fichier (`file_history`, `AppFileHistory`).
- Tout ce qui utilise `graph_log` ou le graphe de symfony-coding.
