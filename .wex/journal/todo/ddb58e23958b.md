# Champ tags iso (twig / Vue / dynamic-form), modèle des champs standardisés

Opened: 2026-11-05
Updated: 2026-11-05
Author: agent:main (Syrtis)

## Besoin

Syrtis a un champ « stamps » (des étiquettes posées sur les messages) à trois endroits, qui ne se ressemblent pas. Il veut **un tronc commun** : un champ générique du DS, identique en twig et en Vue, que Syrtis spécialise par simple préréglage. Ce champ sert de **modèle** aux autres champs standardisés (Syrtis ou non) : un champ métier = un champ générique du DS + des options préréglées.

## Constat

- `assets/components/form/tags-input` :
  - **Vue** (`tags-input.vue`) : `modelValue`, `placeholder`, `separator`, `suggestions` (liste proposée) ;
  - **twig** (`tags-input.html.twig` + `tags-input.ts`) : pas de suggestions → les deux rendus ne sont pas iso.
  - Les tags sont des `.tags-input--tag` simples ; ailleurs le DS dit une étiquette par `marker` (ton, glyphe) — Syrtis affiche ses stamps en `marker` ton `cat-straw`, glyphe `ph:bold/tag`.
- symfony-forms `TagsInputType` (`separator` seul) → `form_theme.html.twig` bloc `tags_input_widget` → twig du DS. Aucune option de suggestions ni d'apparence.
- `FormDefinitionBuilder` : pas de type `tags` dans la norme → le champ part en `type: text`, valeur « a, b » ; `dynamic-form` le dessine en simple texte.

## À faire

- [ ] `tags-input` **iso** twig / Vue : mêmes options, même markup, même comportement.
- [ ] **Suggestions** : une liste fixe (`suggestions`) et/ou une source distante (`suggestions_url`, interrogée sur ce qui est tapé, réponse `[{ value, label }]` ou chaînes) — dans les deux rendus.
- [ ] **Apparence** des tags par `marker` : options `tone` et `glyph` (un ton pour tous les tags du champ).
- [ ] `TagsInputType` : options `suggestions`, `suggestions_url`, `tone`, `glyph`, passées au form theme.
- [ ] Norme des champs : un type `tags` reconnu par `FormDefinitionBuilder` (valeur en liste, options transmises) ; `dynamic-form` le dessine par `tags-input`.
- [ ] Documenter le **patron « champ standardisé »** : un `FormType` qui étend le type générique avec ses options par défaut (`getParent()`), et son pendant Vue qui enveloppe le composant générique avec les mêmes défauts — sans dupliquer le rendu.
