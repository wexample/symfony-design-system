# Select à recherche distante iso (twig / Vue / dynamic-form)

Opened: 2026-11-05
Updated: 2026-11-05
Author: agent:main (Syrtis)

## Besoin

Syrtis choisit le **type de contenu** d'un message parmi un registre (types de la plateforme et du projet) qui peut devenir très long. Il veut un **select qu'on cherche**, ses options lues d'une API à mesure qu'on tape, et pas toutes envoyées avec le formulaire. La valeur est une chaîne (le nom du type), pas une relation : ce n'est pas le cas de `EntitySearchInputType` (symfony-search), qui poste l'id d'un enregistrement.

Même patron que le champ tags (`ddb58e23958b.md`) : un champ générique du DS, préréglé par Syrtis (`ContentTypeInputType` / `content-type-input`).

## Constat

- `form/select-input` (Vue et twig) : options fournies d'avance (`options` / `choices`), pas de recherche.
- `components/select-search` (twig + ts) : un select cherchable, mais sur ses seules options, sans source distante ni pendant Vue, et hors de la famille `form/*`.
- `SelectInputType` (symfony-forms) : `choices` seulement.
- `FormDefinitionBuilder` / `dynamic-form` : le type `select` envoie et dessine toutes ses `choices`.

## À faire

- [x] **Tranché : un champ à part, `form/search-select-input`**, pas une option de `select-input`. Un select porte et valide toutes ses options ; celui-ci n'en tient qu'une partie et poste un texte. Il **remplace `components/select-search`** (supprimé, seule la démo des inputs s'en servait) et en reprend le markup et le style (`select`).
- [x] **Source distante** : `options_url`, `?q=` après une pause de frappe, réponse mots ou `{ value, label }`, nue ou sous `data` / `items`. Logique écrite une fois : `js/Helper/OptionsHelper.ts`, sur lequel `TagsHelper` s'appuie maintenant aussi (côté PHP, `Helper/OptionsHelper`).
- [x] **Valeur courante** par son libellé : `value_label`, sinon l'option qui la porte, sinon demandée à la source (`?q=<valeur>`, l'option de même valeur). Les libellés rencontrés sont gardés : l'option choisie garde le sien quand une recherche ne la liste plus.
- [x] **`SearchSelectInputType`** (et non une option de `SelectInputType`) : parent `TextType`, options `options`, `options_url`, `value_label`. Aucune validation d'appartenance — c'est à l'application, par une contrainte sur le champ.
- [x] Norme : `web/search_select_input.json` (json-schema 1.4.0), kind `search_select`, `options`, `optionsUrl`, `valueLabel` ; `dynamic-form` le dessine.
- [x] Sans aucune option (`options` vides) quand `options_url` est donné : c'est le cas par défaut.

Démo : portfolio `form/inputs` (options propres, et source « countries »), `form/rendered` (twig, libellé demandé à la source), `form/from-server` (dynamic-form) et `form/vue`, sur `DemoCountryInputType` (champ standardisé). Clavier : flèches, Entrée, Échap revient au déclencheur ; « — » en tête quand le champ n'est pas requis.
