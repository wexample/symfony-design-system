## Objectif

Syrtis doit avoir tous les outils de base pour administrer l'app avec l'agent, front et back : modèles, mon compte, comptes (admin). Tout est générique (loader, DS) ; portfolio n'est que le cas de test.

## Documenté

- Loader : `.wex/knowledge/usage/agent-tools.md.j2` (dont « What the user did meanwhile »). DS : `.wex/knowledge/usage/agent.md.j2` (table des composants, forms et champs, « What the user did »).

## Structure (loader)

`AgentToolsService` ; `AgentPage` ; `AgentPointer` ; `AgentHeldResults` ; `AgentNavigation` ; `AgentUserEvents` ; `VueAgentNode` ; `AgentContractService` (PHP, testé, 6 cas).

## Forms (fait, non testé en navigateur)

- Chaque champ est un nœud : `Field` (DS) porte `get`/`set`/`clear`, libellé, état ; `select.ts` ajoute `choose`. Contrats : text (+ variantes par `extends`), select, checkbox (+ switch), date (+ datetime, time), file (lecture seule).
- Le formulaire est un nœud : `Form` (loader) avec `fill`, `submit`, `errors`. Contrat `components/form.ai.yml`, nommé par `form_load` via `agent_contract`.

## Journal des opérations du user (fait, non testé en navigateur)

- `AgentUserEvents` (loader, `sessionStorage`, 10 derniers, même chose refaite = compteur) ; `AgentToolsService.events`, écoute l'événement DOM `agent:event` ; rien n'est noté pendant un appel de l'agent ni 3 s après, ni la page atteinte par sa navigation (`agentLeaving` / `arrivedFromAgent`).
- Le loader note seul : page atteinte (`navigate`), overlay ouvert/fermé (`OverlayService`), form soumis.
- `logAgentEvent(summary, {key, detail})` sur `RenderNode` et dans le mixin Vue global. Émis par : switch, `Field` (sur `change`), button (press), data-table (search, sort, filtres), button-menu (select), pagination.
- Chat : `takeUserEvents()` → `postMessage(content, userEvents)` et `postToolResult(call, callId, results, userEvents)` ; `isUserEvent(entity)` cache les lignes.
- Syrtis : `agent-chat.vue` envoie `userEvents` ; `MessageController::create` les sauve avant le message, même requête, nom `USER_EVENT`, stamps `user_event` + `history`. Scénario à adapter côté user.
- Onglet « User events » dans la console de debug (`develop-agent-events`) : nouvelle entrée, manifest regénéré, watcher à relancer.

## Cadres par couche de page (fait, non testé en navigateur)

- Décision : un cadre reste tant que l'utilisateur ne l'a pas enlevé ou que l'agent n'a pas pointé ailleurs ; pas d'effacement sur action, pas d'option multi-focus (`focus({nodes})` suffit).
- `AgentFrameLayer` : une couche par couche de page, la page sous le voile (`--z-modal - 2`), une dans chaque overlay (`OverlayService.layerOf`), cadres placés depuis l'origine de leur couche. `AgentPointer` relâche par couche cliquée.
- `Form.submit` presse le bouton par son nœud (`AgentToolsService.nodeFor`) : ripple, cadre, confirmation.
