# Skin axis — 4th theming dimension

## State

The axis exists. `skin` is a loader usage like `color_scheme`, declared after
it in the loading order. `margins` was renamed `density` at the same time, so
the model reads: `color_scheme` (the light), `density` (how much per screen),
`skin` (how things are drawn), `animations` (motion — still without any file).

What moved, pixel-identical (the 80 token declarations of the dashboard layout
compile byte-for-byte the same, only the selector changed):

- `layouts/default/layout.density.<value>.scss` — `--space-*`, `--size-*`,
  `--font-size-*` on `.usage-density-<value>`.
- `layouts/default/layout.skin.<value>.scss` — `--radius-*`, `--shadow-*`,
  `--border-*` (the line, never its colour) on `.usage-skin-<value>`.
- `layouts/dashboard/` has both, delegating to default.
- Every app layout on a DS layout carries the entry files, as it does for the
  colour scheme.
- Demo: *Foundations › Skin* (radii, shadows, borders, separators); the radii
  left the spacing page.

## Where the cut is

- Colour → `color_scheme`, always. A skin says which *role* a component takes
  (`--tabs-surface: var(--color-info-8)`), the scheme says what that role is.
- Spacing, sizes, type *size* → `density`. Font *family* and weight → `fonts`.
- Radii, shadow geometry, border width and style, separators, focus ring width
  → `skin`. Intrinsic shapes (a round avatar, a pill switch) are not skin
  decisions and stay written in the shape.
- Tokens first; a per-component file (`tabs.skin.<value>.scss`, which the
  loader already supports for any render node) only when tokens cannot say it.

## Done since

- The two skins are separated. `default` is gone as a name — a mixture names
  nothing — and the axis carries `basic` (flat and square, what the system
  looked like all along) and `soft` (capsule controls, generous surfaces, no
  separators, depth instead of lines). The config defaults to `basic`.
  `--radius-control` parted from what is now `--radius-box` on the way, the day
  `soft` turned a textarea into a lozenge.
- The radius scale is geometric (`0.125 / 0.25 / 0.5 / 1rem`) and the roles are
  three: `control`, `box` — anything holding something, field or block or toast
  alike — and `media`, plus the pill. `field` and `surface` had been two roles
  for a while and never diverged, so they were merged.
- Shadow colour no longer leaks out of the skin. The scheme mixin declares
  `--shadow-color` (`var(--color-absolute-dark)` on both faces, overridable
  after the include like any semantic token), and `mixins/_shadow.scss` casts
  each layer as `color-mix(in srgb, var(--shadow-color) N%, transparent)`,
  the percentages being the old alphas unchanged. Rendering is identical;
  only the ownership moved. Compiled and diffed against the previous output
  with dart-sass 1.99 — the four `--shadow-N` lines and the one new token are
  the whole difference.

## What remains

1. **`soft` has not been walked through page by page.** It exists to prove the
   roles carry and to give the axis something to switch to. Expect surprises
   wherever a shape draws its own corner.

2. **Dark-face shadows.** With the colour in the scheme, the dark face can now
   say something other than black — but it cannot say *heavier*, the skin
   holds the percentages. If dark ever needs more weight than light, the
   scheme gets a second token (a strength) or the skin reads two colours; not
   decided, not needed yet.

3. **Switching.** No header switch: the debug panel's *Usages* tab lists every
   value the config declares. A `select` may come later, and above it presets
   — a named theme setting several axes at once (`windows95` = skin + colour
   scheme) — which is how a third-party look joins without breaking the axes.

4. **Border roles**, if a skin ever needs a control border unlike a surface
   border — today `--border-default` serves both and nothing diverges.

5. `animations` is a configured axis with no file, and its list is down to
   `none` — a value that loads nothing is a switch that does nothing. Making it
   real means motion tokens and rewriting the hard-coded `transition` durations
   across shapes. A usage swap itself is a clean cut by decision: a transition
   over the swap was tried and dropped, it read worse than the cut.

6. `windows95`, once the rest is settled: bevels, no radius, system font — its
   colours come through roles mapped onto a `win95` colour scheme, never as hex
   in the skin.
